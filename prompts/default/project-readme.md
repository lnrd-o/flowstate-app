Write or update README.md for this project, based only on what is really in the repository.

Steps:
1. Explore the project: entry points, package manifest, scripts, configuration, tests and folders. Run the install and test commands you document if it is safe to do so, to confirm they work.
2. Write README.md with these sections: name and one-sentence purpose, features, requirements, installation, usage (with real commands and short examples), configuration, project structure (short tree with one-line comments), how to run the tests, and licence if a LICENSE file exists.
3. Do not invent features, badges, URLs or commands. If something is unclear, add a "TODO: confirm" note and list the open questions in your reply.
4. Keep it concise and scannable; prefer short paragraphs, lists and fenced code blocks.
5. If a README.md already exists, keep its useful content and save a copy of the previous version to artifacts/README.previous.md before replacing it.
